# Input Server 开发计划

## 1. 目标

实现一个本地 HTTP 服务器（`input_server.exe`），接收 Chrome Extension 发来的 JSON 指令，调用 Windows `SendInput` API 执行键盘/鼠标操作，实现 AI 平台的自动粘贴与发送。

```
Chrome Extension (ChatFree)
    ↓  HTTP POST JSON  →  http://127.0.0.1:12306
input_server.exe (C# Native AOT)
    ↓  P/Invoke
Windows SendInput API
```

## 2. 技术选型

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | C# (.NET 9) | LTS 版本，Native AOT 成熟稳定 |
| HTTP | `Kestrel`（`WebApplication.CreateSlimBuilder`） | 纯托管实现，不走 http.sys，无需管理员权限 |
| Windows API | 直接 P/Invoke | 调用 `SendInput`，结构简单无需源生成器 |
| 编译目标 | Native AOT (`PublishAot=true`) | 单文件 exe，4-8MB，无需 .NET 运行时 |
| 端口 | `127.0.0.1:12306` | 仅监听 localhost，不对外暴露 |

> **为什么不用 HttpListener？** `HttpListener` 在 Windows 上底层走 `http.sys`，需要管理员权限注册 URL 前缀（或用 `netsh http add urlacl` 手动配置）。Kestrel 是纯托管 TCP socket + HTTP 解析，所有平台均无需特殊权限。

## 3. 通信协议

### 3.1 请求格式

Extension 向 `POST http://127.0.0.1:12306/execute` 发送 JSON：

```json
{
  "actions": [
    { "type": "key", "key": "V", "modifiers": ["Ctrl"] },
    { "type": "key", "key": "Enter" },
    { "type": "type", "text": "plain text to type" },
    { "type": "click", "x": 100, "y": 200 },
    { "type": "wait", "ms": 300 }
  ]
}
```

### 3.2 指令类型

| type | 参数 | 说明 |
|---|---|---|
| `key` | `key: string`, `modifiers?: string[]` | 按下组合键（如 Ctrl+V） |
| `type` | `text: string` | 逐字符输入文本（复杂字符用 SendInput KEYEVENTF_UNICODE） |
| `click` | `x: number`, `y: number` | 鼠标点击指定坐标 |
| `wait` | `ms: number` | 等待指定毫秒 |

### 3.3 响应格式

```json
{ "ok": true }
// 或
{ "ok": false, "error": "error message" }
```

### 3.4 健康检查

`GET http://127.0.0.1:12306/health` → `{ "ok": true, "version": "0.1.0" }`

## 4. 服务端模块划分

```
server/
├── 需求.md
├── 开发计划.md
├── Program.cs           # 入口：启动 HTTP 监听，路由分发
├── InputExecutor.cs     # 核心：解析指令，调用 Windows API
├── NativeMethods.cs     # Windows API P/Invoke 声明（SendInput 等）
├── CommandModels.cs     # JSON 序列化的请求/响应类型
└── InputServer.csproj   # 项目文件（含 PublishAot 配置）
```

### 4.1 Program.cs — HTTP 服务器

- 使用 `WebApplication.CreateSlimBuilder()` 创建 Kestrel 服务，监听 `http://127.0.0.1:12306`
- 路由：
  - `GET /health` → 返回健康状态
  - `POST /execute` → 解析 JSON → 调用 `InputExecutor` → 返回结果
- 启动时输出提示信息到控制台
- 优雅退出处理（`app.Services.GetRequiredService<IHostApplicationLifetime>()`）

### 4.2 CommandModels.cs — 数据模型

```csharp
public record InputCommand(string Type, string Key, string[] Modifiers, string Text, int X, int Y, int Ms);
public record ExecuteRequest(InputCommand[] Actions);
public record ExecuteResponse(bool Ok, string Error = null);
```

**Native AOT 要求**：必须使用源生成器序列化，不能依赖反射版 `JsonSerializer`。需要在项目内声明一个 partial context 类：

```csharp
[JsonSerializable(typeof(ExecuteRequest))]
[JsonSerializable(typeof(ExecuteResponse))]
internal partial class AppJsonContext : JsonSerializerContext { }
```

并在反序列化时传入该 context：`JsonSerializer.Deserialize(req, AppJsonContext.Default.ExecuteRequest)`。

### 4.3 NativeMethods.cs — Windows API

- `SendInput` — 核心 API，发送键盘/鼠标事件（已完全取代 `keybd_event`，无需备选方案）
- 常量定义：`INPUT_KEYBOARD`, `INPUT_MOUSE`, `KEYEVENTF_KEYUP`, `KEYEVENTF_UNICODE`, `MOUSEEVENTF_*`
- 组合键实现：在 `INPUT[]` 数组中依次放置修饰键按下→主键按下→主键释放→修饰键释放，一次 `SendInput` 调用完成

### 4.4 InputExecutor.cs — 指令执行

- `ExecuteAsync(InputCommand action)` — 按类型分发：
  - `key` → 模拟组合键（按下修饰键 → 按主键 → 释放修饰键）
  - `type` → `SendInput` + `KEYEVENTF_UNICODE` 逐字符输入
  - `click` → `SetCursorPos` + 鼠标按下/释放事件
  - `wait` → `Task.Delay`
- 错误处理：捕获异常，返回 Error 信息

## 5. Chrome Extension 改造

### 5.1 新增模块

```
server/
└── （服务端）

Extension 侧新增/修改：
├── modules/server-client.js   # 新增：与 input_server 通信的客户端模块
```

### 5.2 server-client.js 职责

- `checkServerHealth()` — 检测 server 是否在运行
- `sendActions(actions)` — POST JSON 到 server
- `pasteAndSubmit()` — 预设动作序列：Ctrl+V → wait → Enter

### 5.3 与现有流程集成

集成点：`input-area.js` 的 `copyComposed()` → 复制成功 → `collapseFloatingPanel()` → **等待焦点回归 AI 平台输入框** → 调用 server 执行粘贴+发送。

**时序设计**：

```
copyComposed()  // 写入剪贴板
  → collapseFloatingPanel()   // 隐藏面板，焦点开始回归
  → focusAIInputBox()         // 主动 focus AI 平台的输入框（通过 site-*.js）
  → wait 150ms                // 等待焦点稳定
  → server pasteAndSend()     // POST /execute: Ctrl+V → wait 100ms → Enter
```

**降级处理**：server 不可用时静默回退到现有"仅复制"行为（用户手动 Ctrl+V）。`checkServerHealth()` 在扩展启动时预检一次，避免每次粘贴都超时等待。

在 `manifest.json` 中不需要额外权限（localhost 通信不受 `host_permissions` 约束，且 `127.0.0.1` 无 Mixed Content 限制）。

## 6. 开发步骤

### Phase 1：最小可用版本（v0.1）

1. **创建 C# 项目骨架**
   - `dotnet new console` → 创建项目
   - 配置 `.csproj`：`<PublishAot>true</PublishAot>`
   - 使用 `WebApplication.CreateSlimBuilder()` 创建 Kestrel 监听器
   - 添加 `JsonSerializerContext` 源生成器（Native AOT 强制要求）

2. **实现 SendInput P/Invoke**
   - 完成 `key` 指令（Ctrl+V 粘贴）
   - 完成 `wait` 指令
   - 先硬编码测试：收到 POST → Ctrl+V → wait 200ms → Enter

3. **手动测试**
   - 启动 `input_server.exe`
   - 用 curl/PowerShell 发 POST 请求验证

4. **Extension 侧接入**
   - 创建 `server-client.js`
   - 修改 `input-area.js` 的 `copyComposed()`：复制后 → 聚焦 AI 输入框 → 调用 server 粘贴发送
   - 在 `site-*.js` 各平台适配模块中增加 `focusInput()` 方法，确保焦点回归正确位置
   - `checkServerHealth()` 预检 + 不可用时静默降级
   - 端到端测试

### Phase 2：完善（v0.2）

5. **完善指令类型**
   - `type` 指令（Unicode 文本输入）
   - `click` 指令（鼠标坐标点击）
   - 组合键支持（多修饰键）

6. **健壮性**
   - Server 未运行时 Extension 的降级处理（回退到手动粘贴）
   - 超时处理
   - 错误提示

7. **编译与发布**
   - 使用 `dotnet publish` 命令编译
   - 测试独立 exe 在不同 Windows 环境下的运行

### Phase 3：优化（v0.3+）

8. **稳定性增强**
   - 多 action 序列的原子性（单次 POST 中的所有 action 作为一个事务）
   - 并发请求的排队处理（后续请求在前一个完成前不执行）
   - `type` 指令支持更完整的 Unicode 字符集

## 7. 风险与注意事项

| 风险 | 应对 |
|---|---|
| SendInput 不生效 | 确保 Extension 与 server 在同一用户会话下运行；SendInput 是 Microsoft 推荐的唯一键盘模拟 API |
| Native AOT 编译失败 | 避免使用反射、动态代码生成；JSON 序列化使用源生成器（`JsonSerializerContext`）；P/Invoke 声明保持简单 |
| 杀毒软件误报 | Native AOT 编译比 PyInstaller 误报概率低很多；必要时代码签名 |
| 焦点未回到 AI 输入框 | Phase 1 即在 `site-*.js` 中实现 `focusInput()`，粘贴前主动聚焦；Server 端 `wait` 给焦点稳定留时间 |
| Manifest V3 localhost 限制 | localhost 豁免 host_permissions；`127.0.0.1` 不受 Mixed Content 限制 |
