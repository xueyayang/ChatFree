# Input Server 测试单

## 测试环境

- Server: `dotnet run` → `http://127.0.0.1:12306`
- 测试工具: PowerShell `Invoke-RestMethod`

---

## API 测试（不依赖焦点切换）

### 1. 健康检查

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:12306/health
```

**预期**: `@{ok=True; version=0.1.0}`

**结果**: ✅ 通过

---

### 2. 纯 wait 指令 — 验证 server 不阻塞

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:12306/execute -Method POST -Body '{"actions":[{"type":"wait","ms":500}]}' -ContentType "application/json"
```

**预期**: `@{ok=True}`

**结果**: ✅ 通过

---

### 3. 空 actions 错误处理

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:12306/execute -Method POST -Body '{"actions":[]}' -ContentType "application/json"
```

**预期**: HTTP 400 + `@{ok=False; error="Missing or empty actions array"}`

**结果**: ✅ 通过

---

### 4. 未知指令类型

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:12306/execute -Method POST -Body '{"actions":[{"type":"unknown"}]}' -ContentType "application/json"
```

**预期**: `@{ok=False; error="Unknown action type: unknown"}`

**结果**: ✅ 通过

---

### 5. 缺少 actions 字段

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:12306/execute -Method POST -Body '{}' -ContentType "application/json"
```

**预期**: HTTP 400

**结果**: ✅ 通过

---

## 键盘/鼠标测试（通过 Extension 端到端测试）

以下测试不能通过 curl 进行（SendInput 会注入到终端自身），需要在浏览器场景下验证：

### E1. Ctrl+V 粘贴
- 在 ChatFree 输入框中输入文字 → Copy → 观察是否正确粘贴到 AI 平台输入框

- 同上，粘贴后自动回车发送

### E3. type 文本输入
- 使用 `type` 指令逐字符输入文本

### E4. click 鼠标点击
- 点击指定屏幕坐标

### E5. 降级处理

## 已知问题

**SendInput 卡死**: Type/Paste/Full 等涉及按键注入的测试，因焦点可能落在浏览器自身窗口，导致 SendInput 注入回自身，造成浏览器和 server 卡死。需增加注入前焦点确认机制。
