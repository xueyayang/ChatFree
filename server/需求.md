### 核心结论：首选 C# (C# Native AOT)

你可能会有点意外，为什么不是 Rust 或 C++？因为在 2026 年的今天，**C# 的 Native AOT（原生提前编译）** 已经非常成熟了。它完美地卡在了“开发效率”与“独立小体积”的甜点位上。

如果因为某些原因不想用 C#, **Rust** 是唯一的备选。

---

## 四种方案的横向对比

我们用你最关心的几个指标（1-5星，三星及格，五星完美）来打个分：

| 语言 | 开发速度 (快) | 依赖与环境 (省心) | 体积与独立性 (小/无依赖) | 调用 Windows API 难度 |
| --- | --- | --- | --- | --- |
| **C# (Native AOT)** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ (~5MB 独立) | ⭐⭐⭐⭐ (非常成熟) |
| **Rust** | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ (~3MB 独立) | ⭐⭐⭐⭐⭐ (官方库极好) |
| **C++** | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ (<1MB 独立) | ⭐⭐⭐⭐⭐ (原生支持) |
| **Python** | ⭐⭐⭐⭐ | ⭐ | ⭐ (打包后 40MB+, 易报毒) | ⭐⭐⭐ (需要包装库) |

## 为什么强烈推荐 C# (.NET 8/9/10)?

过去大家觉得 C# 体积大、要装 .NET 运行时。但现在的 C# 完全不一样了。

### 1. 真正实现“独立、体积小” (Native AOT)

你只需要在项目配置文件（.csproj）里加一行：

```xml
<PublishAot>true</PublishAot>

```

编译出来的就是一个**没有任何依赖的独立 input_server.exe**。

* 体积大约在 **4MB - 8MB** 之间。
* 用户电脑上**不需要安装任何 .NET 运行时**，双击直接跑。

### 2. 开发极快，生态现成

* **HTTP Server**：C# 自带的 HttpListener 或者最轻量化的 WebApplication.CreateSlimBuilder（专门为 AOT 优化的微型 Web 服务），几行代码就能搭好一个高性能的本地接口。
* **Windows API (SendInput)**：通过官方的 Microsoft.Windows.CsWin32 源生成器，或者直接用现成的第三方库（如 InputSimulator），调用底层的鼠标键盘控制极其简单，不需要像 C++ 那样处理复杂的内存指针。

### 3. 环境简单

你只需要下载一个 Visual Studio 或者 VS Code + .NET SDK，开箱即用，不需要折腾 C++ 那种复杂的 CMAKE 或工具链。

## 为什么不选其他三个？

### ❌ Python：第一个排除

* **体积大、发布难**：Python 必须用 PyInstaller 打包，它其实是把整个 Python 解释器和一堆 .dll 塞进 exe 里，解压运行。体积少说 40MB 起步。
* **容易被杀毒软件误杀**：PyInstaller 打包的独立 exe 是 Windows Defender 和各种杀毒软件的“重点照顾对象”，经常无故报毒。
* **环境碎**：各种 pip 依赖和虚拟环境，后期维护很头疼。

### ⚠️ C++：开发太慢，容易写出 Bug

* 虽然 C++ 编译出来体积最小（可能只有几百 KB），调用 SendInput 最原生，但**开发效率太低**了。
* 写一个稳定、不内存泄漏的 HTTP 服务器在 C++ 里挺麻烦的（即使有 cpp-httplib 这样的单头文件库）。
* 如果你不是资深 C++ 程序员，处理网络数据和 Windows 消息队列会浪费大量时间。

### ⚠️ Rust：很好的备选，但有学习成本

* Rust 编译出的 exe 极其稳定、体积小（3MB 左右），且有微软官方维护的 windows-rs 库，调用 SendInput 很安全。
* **缺点**：Rust 的学习曲线陡峭。如果团队里没人熟悉 Rust，光是搞懂“所有权”和“生命周期”，或者在处理 HTTP 异步请求时和编译器“吵架”，就会严重拖慢首版开发速度。

## 落地建议：C# 极简实现思路

既然 Chrome 插件在本地和 input_server.exe 通信，你的 Server 只需要监听 localhost 的一个固定端口（比如 127.0.0.1:12306），接收 JSON 格式的指令。

在 C# 中，一个最基础的、支持 Native AOT 的本地输入服务器代码结构大概长这样（非常直观）：

```csharp
using System.Net;
using System.Text.Json;

// 1. 启动超轻量 HTTP 监听
var listener = new HttpListener();
listener.Prefixes.Add("http://127.0.0.1:12306/");
listener.Start();
Console.WriteLine("Input Server 正在运行...");

while (true)
{
    var context = await listener.GetContextAsync();
    using var reader = new StreamReader(context.Request.InputStream);
    var jsonString = await reader.ReadToEndAsync();
    
    // 2. 解析来自 Chrome 插件的鼠标键盘指令
    var command = JsonSerializer.Deserialize<InputCommand>(jsonString);
    
    // 3. 调用 Windows API (此处可以用现成库或 P/Invoke 封装的 SendInput)
    ExecuteWindowsInput(command);

    context.Response.StatusCode = 200;
    context.Response.Close();
}

public record InputCommand(string Type, int X, int Y, string Key);

```
